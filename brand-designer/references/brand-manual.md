# Illustrated brand manual / Manual de Marca

Produce a usable, designed reference that demonstrates the identity as one system. Adapt language, tone, length, page format, and chapter names to the business and intended readers; the Aulora reference is a depth and presentation benchmark, not a 36-page quota or a template to copy.

For an existing brand, inventory approved assets and documented rules first. Identify missing specifications; propose additions without silently inventing approvals. Manual production does not itself authorize redesign.

## Flexible editorial structure

| Chapter | Content and visual evidence |
| --- | --- |
| Opening | Cover, identity/version/status, contents, concise brand premise; section openers where useful |
| Brand platform / Plataforma de marca | Purpose, mission, vision, promise, positioning, audiences, values and personality; connect aspirations to substantiated claims |
| Name / El nombre | Approved name, meaning, derivation, pronunciation, spelling/capitalization, tagline and product family where relevant |
| Symbol and logotipo | Symbol and wordmark shown separately and together; rationale, geometry/construction where useful, horizontal/vertical signatures, monochrome/reverse/background variants, clear space, minimum sizes, illustrated incorrect uses |
| Color | Swatches, semantic roles, usage proportions if meaningful, allowed combinations, digital values and qualified print specifications |
| Typography | Real type specimens, roles, weights, hierarchy, spacing, fallbacks and representative layouts; distinguish logo lettering from general type |
| Visual language | Repeatable motifs, grids, whitespace, imagery direction, icons and illustration; motion and reduced-motion behavior when relevant |
| Voice | Personality translated into writing rules, vocabulary, tone by situation and realistic on-brand examples |
| Applications | Rendered examples for the business's real channels, with dimensions and production notes; demonstrate the same system across media |
| Technical appendix / Anexo técnico | Implementation specifications and verified asset references; use [technical-appendix.md](technical-appendix.md) |

Keep approved rules in the final manual. If a manual is presented before all decisions are approved, label the release and affected proposals as draft. Do not manufacture assets or measurements merely to fill the chapter structure.

## Cohesion and editorial design

Define a central creative idea and show how the name, symbol, typographic character, colors, patterns, language, and applications express it. Motifs should have repeatable rules. Explain useful decisions without forcing a symbolic story onto every detail.

Set a consistent page grid, margins, hierarchy, captions, numbering, and section navigation. Balance large visual demonstrations with concise rules. Match the manual's own design to the brand: do not apply Aulora's arch motif, gold/navy palette, or serif aesthetic to unrelated businesses. A manual must include actual artwork and rendered applications, not just a prose checklist or descriptions of imagined mockups.

Select applications from the brief. Education may call for certificates, family communications, dashboards, stationery and institutional co-branding; another business may need packaging, menus, signage, uniforms or sales material. Clearly label mockups, production-ready layouts and functional interfaces. Decorative seals, sample QR codes and interface drawings are not working verification or product features. Use fictional sample identities/data; do not fabricate live contact details or product claims.

Co-branding needs explicit hierarchy, separation, logo sizing and palette interaction rules when multiple organizations appear. Do not extrapolate one client's hierarchy to every business.

## Sources, production and handoff

Deliver an editable layout source, reviewed PDF, and separately usable brand assets. Choose a suitable source format with available tools, retain linked assets and document font dependencies. A Markdown outline alone is not an editable visual layout equivalent. If a requested format cannot be produced, record the limitation in the manifest and do not label it delivered.

Render and inspect every final PDF page at readable scale using available PDF tools; a contact sheet helps check rhythm but does not replace detailed legibility checks. Inspect artwork, typography, whitespace, clipping, repeated rules, page numbers and contents references. Check application examples against the same approved master assets. Revise and rerender affected pages before delivery.

Use one source of truth for values repeated across manual, appendix, tokens and assets. Keep print effects and materials labeled as simulations or production recommendations until verified. Include manual source/PDF paths, appendix, linked assets and unresolved limitations in the release manifest, then use the existing release approval gate.
